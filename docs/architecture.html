Layer Deep Dive

1. Entry Point — src/index.ts

Single file that wires everything together using Commander.js.

ResponsibilityHow
CLI parsingnew Command().name('llm-collab').version(...)
Command registrationEach command module exports a Command instance, added via .addCommand()
Global options--debug, --config, --version
Error boundaryTop-level catch with typed errors and chalk-colored output

2. Commands — src/commands/

Thin orchestration layer. Each command file:

  • Exports a Commander Command with options/arguments
  • Loads config via ConfigManager
  • Instantiates required services
  • Calls service methods and formats output
  • Handles errors with typed error classes + process.exit(1)

3. Services — src/services/

Thick business logic. Services:

  • Manage authentication (API keys, OAuth tokens, refresh logic)
  • Wrap external REST/GraphQL APIs with typed responses
  • Cache responses with TTL-based expiry
  • Throw typed errors — commands catch and format
  • Are instantiated per-request (no global singletons except ConfigManager)
  • Retry with exponential backoff on transient failures (p-retry)

Request Data Flow

CLI Command Execution

User -------> src/index.ts (Commander.js parses argv) | v Command Handler (e.g. src/commands/github.ts) | |--> ConfigManager.load() -> reads config.json + ENV | |--> Service instantiation -> e.g. new GitHubService(config) | |--> Service method call -> Octokit REST/GraphQL with auth | |--> HookManager.emit('onToolCall') -> audit + cost tracking | v Output -------> logger.passThrough() -> chalk-formatted result to stdout

MCP Tool Execution (AI Agent → Tool)

AI Agent -------> MCP Transport (stdio | Express HTTP+SSE) | v MCP Server (protocol handler) | |--> Capability Check -> is this tool registered? (gated by config) | |--> Tool Lookup -> MCPService.registry[toolName] | |--> MCPToolContext -> injects authenticated service instances | |--> Tool Handler -> calls service method, never throws | |--> HookManager -> audit log + cost tracking + secret scan | v Response -------> MCPToolResult -> { success, data } | { success: false, error }

Chronicle Knowledge Flow

Input -------> Chronicle Service (text, code, decisions) | |--> Entity Extraction -> LLM identifies files, functions, concepts | |--> Embedding Generation -> vector via Anthropic Voyage / OpenAI / Ollama | |--> better-sqlite3 Store -> items + entities + relations + timeline | v Query -------> Hybrid Search (FTS5 keyword + vector cosine similarity) | |--> Graph Traversal -> follow entity relationships | |--> RAG Assembly -> context from search + graph | v Answer -------> LLM Response -> answer with citations to source items

Multi-Agent Delegation

User Request -------> Orchestrator (Opus 4.6 — analyzes, delegates) | |--> Planner (Opus 4.6) -> researches codebase, creates plan | | | v | Implementation Plan (files, changes, edge cases, tests) | |--> Coder (Sonnet 5) -> implements plan, uses context7 MCP | |--> Designer (Sonnet 5) -> UI/UX, terminal interfaces | v Orchestrator -------> Validates -> integrates results, verifies, reports

Chronicle — Knowledge System

Chronicle is the persistent knowledge layer that survives across sessions, agents, and tools. It combines a better-sqlite3 store, vector embeddings, a knowledge graph, and temporal versioning.

Schema

TablePurposeKey Columns
itemsRaw knowledge entriesid, content, metadata (JSON), embedding (BLOB), created_at
entitiesExtracted conceptsid, name, type (file/function/decision/concept/person), properties (JSON)
relationsEntity connectionsfrom_id, to_id, type (depends_on/authored_by/decided_in/blocks/implements)
timelineTemporal snapshotsid, item_id, snapshot (JSON), timestamp

Entity Types

TypeExamplesAuto-Extracted From
filesrc/services/auth.tsCode references, imports
functionvalidateJWTFunction definitions, calls
decision"Use JWT over sessions"Conversations, ADRs
concept"authentication", "rate limiting"Topic extraction
person"@alice", "@bob"Mentions, authorship
issue"GH-123", "LIN-456"Issue references

Relation Types

RelationExample
depends_onauth.ts depends_on jwt-utils.ts
implementsvalidateJWT implements "JWT validation decision"
blocksGH-123 blocks GH-456
authored_by"JWT decision" authored_by @alice
decided_in"Rate limiting approach" decided_in session-2024-03

Query Modes

1. Keyword Search SQLite FTS5 full-text search over item content and entity names Example: chronicle search "JWT rotation" 2. Semantic Search Cosine similarity between query embedding and stored embeddings Example: chronicle search "how does authentication work" --semantic 3. Graph Traversal Follow entity relationships to find connected knowledge Example: chronicle graph --entity "auth_middleware" --depth 2 4. NL Question Answering RAG: search -> context assembly -> LLM answer with citations Example: chronicle ask "why did we choose JWT over sessions?" 5. Timeline Query What was known at a specific point in time Example: chronicle timeline --since 2024-01-01 --entity "auth"

How to Build This From Scratch

12 phases, ordered by dependency. Each phase produces a usable increment.

Phase 1: Foundation COMPLETE

  1. Initialize Node.js Project

    package.json with scripts (dev, test, build, lint, typecheck, pkg). tsconfig.json with strict mode, ESM output. tsup.config.ts for bundling. Entry point at src/index.ts.

  2. Commander.js CLI Router

    Set up src/index.ts with commander. Register one command to validate the pattern. Commander handles argument parsing, help text, and option validation.

  3. Configuration System

    ConfigManager singleton: CLI args > LLM_COLLAB_* env > ~/.llm-collab/config.json > defaults. Validate with Zod. llm-collab config command.

  4. Setup Wizard & Logger

    Inquirer.js interactive prompts for llm-collab setup. Logger with chalk colors, structured JSON mode, LLM_COLLAB_DEBUG env var. Respects NO_COLOR.

Phase 2: LLM Integration COMPLETE

  1. AI Service Abstraction

    Provider interface via Vercel AI SDK: @ai-sdk/anthropic, @ai-sdk/openai. Unified streaming. Model selection with fallback chains. Ollama and OpenRouter support.

  2. Relay Server + Chat

    Express.js HTTP proxy injects API keys (llm-collab relay). Interactive chat REPL with streaming, history, and cost display (llm-collab chat).

  3. Cost Tracking

    Model pricing data, per-session/per-model accumulation, budget alerts. EventEmitter-based hook: onInference fires with token counts and cost.

Phase 3: MCP Server COMPLETE

  1. MCP Core + Tool Registry

    Use @modelcontextprotocol/sdk. Tool registry: name → JSON Schema → handler. MCPToolContext for service injection. Handlers never throw.

  2. Capability Gating

    Only register tools for configured integrations. github_* tools appear only when config.integrations.github.token exists. Progressive disclosure.

  3. Multi-Transport

    stdio (Claude Code default), Express HTTP+SSE (web clients), ws WebSocket (A2A). Same handlers, different transport layer.

Phase 4: Integrations COMPLETE

  1. GitHub Service + MCP Tools

    Octokit REST + GraphQL via @octokit/rest and @octokit/graphql. 10 MCP tools: github_get_issue, github_search_issues, github_list_issues, github_create_issue, github_get_pr, github_list_prs, github_create_pr, github_ci_status, github_get_repo, github_add_comment. CLI: github issues list/get/search/create, github prs list/get, github ci.

  2. Linear Service + MCP Tools

    @linear/sdk GraphQL client. 7 MCP tools: linear_get_issue, linear_search_issues, linear_list_issues, linear_create_issue, linear_update_issue, linear_list_teams, linear_list_projects. CLI: linear issues list/get/search/create, linear teams, linear projects. Capability gating: tools only registered when integration is configured.

Phase 5: Chronicle COMPLETE

  1. SQLite Store + Embeddings

    Per-project better-sqlite3 database at ~/.llm-collab/chronicle/<hash>/chronicle.db. Items, entities, relations, timeline tables. FTS5 full-text search. WAL mode. Cosine similarity vector search. Embedding generation via Vercel AI SDK (OpenAI/Ollama providers).

  2. Knowledge Graph + NL Query

    Entity types: file, function, decision, person, issue, concept. Relation types: depends_on, authored_by, decided_in, blocks, implements, related_to. Graph traversal with depth control. RAG-based NL Q&A with citations via QueryEngine. 8 MCP tools: chronicle_search, chronicle_read, chronicle_write, chronicle_ask, chronicle_graph, chronicle_timeline, chronicle_entity, chronicle_stats. CLI: chronicle init/push/search/ask/graph/timeline/stats.

Phase 6: Agent System COMPLETE

  1. Sub-Agent Definitions

    src/config/sub-agents.ts — SubAgentConfig interface and 3 domain agents (github-expert, linear-expert, chronicle-expert) with system prompts, scoped tools, and model assignments. generateAgentMarkdown() exports each as YAML frontmatter + markdown.

  2. Agent Launcher Service

    src/services/agent-service.ts — AgentService spawns Claude Code, Codex, or OpenCode via child_process.spawn(), builds env with provider API keys, generates MCP config, and installs domain agents to ~/.claude/agents/ idempotently via installDomainAgents(). Includes complexity routing (low/medium/high → model).

  3. Agent CLI

    src/commands/agent.ts — agent claude/codex/opencode (-p, -r, --model, --live), agent install (idempotent, --force), agent list (--json). Wired into src/index.ts as the 11th command.

Phase 7: Skills System COMPLETE

  1. Bundled Skills

    src/data/bundled-skills.ts — BundledSkill interface and 3 skills (code-review, chronicle-capture, cost-report) embedded as TS strings with YAML frontmatter. getSkillByName() and searchSkills() helpers.

  2. Skills CLI

    src/commands/skills.ts — skills list (--json), skills install [name] (single skill or all bundled, --force), skills search <query>. Installs to ~/.claude/skills/, idempotent — never overwrites user edits. Wired into src/index.ts as the 12th command.

  3. Setup Wizard Integration

    src/commands/setup.ts — prompts to install domain agents and bundled skills after config save.

Phase 8: Hooks & Auditing COMPLETE

  1. Hook Manager + Cost Hook

    src/hooks/hook-manager.ts — EventEmitter-based lifecycle hooks: onToolCall, onInference, onSessionStart, onSessionEnd, onError, onBudgetAlert. Typed contexts, enable/disable toggle. src/hooks/cost-hook.ts registers on inference events, tracks session spend, and fires budget alerts when a threshold is exceeded.

  2. Secret Scanner + Webhooks

    src/hooks/secret-scanner.ts — regex patterns for AWS keys, GitHub tokens, API keys, private keys, and generic secrets, with warn or block modes and excerpt masking. src/hooks/webhook.ts — sends session_start, session_complete, session_failed, error, and budget_alert events to Slack, Discord, or a generic webhook URL (auto-detects Slack format). Wired into src/index.ts, which initializes the cost hook and webhooks from config and emits session start/end/error events.

Phase 9: A2A Protocol COMPLETE

  1. Protocol Types

    src/agent/a2a/protocol.ts — JSON-RPC 2.0 message types (JsonRpcRequest, JsonRpcResponse, JsonRpcNotification), MethodRegistry class for handler registration, helper functions (createRequest, parseMessage, isRequest, isResponse, isNotification).

  2. WebSocket Server

    src/agent/a2a/server.ts — A2AServer class built on the ws package with built-in methods (shell.execute, file.read, file.write, agent.delegate, rpc.methods), client tracking, broadcast, and audit logging.

  3. WebSocket Client

    src/agent/a2a/client.ts — A2AClient class: WebSocket client, promise-based RPC calls with timeout, notification handlers, and typed convenience methods (shellExecute, fileRead, fileWrite, delegate, listMethods).

Phase 10: Error Handling & Resilience COMPLETE

  1. Retry Strategies

    src/utils/retry.ts — withRetry() wraps p-retry for exponential-backoff retries on transient failures, re-exports AbortError to stop retrying immediately on non-retryable errors, and a CircuitBreaker class with configurable failure threshold and reset timeout that tracks closed/open/half-open state.

  2. Payload Cleaning

    src/utils/payload.ts — cleanPayload() truncates large API responses for LLM consumption with configurable maxLength, maxArrayItems, maxDepth, and field stripping; summarizePayload() produces a compact one-line summary of an object.

Phase 11: Testing COMPLETE

  1. Unit & Integration Tests

    73 tests across 8 files: error classes, retry/circuit breaker, payload cleaning, secret scanner, hook manager, A2A protocol, ConfigManager, bundled skills. All passing via Vitest.

Phase 12: Distribution COMPLETE

  1. Build & Shell Completions

    tsup ESM bundle (~192 KB). pnpm link --global for local install. Shell completions for bash/zsh/fish. Comprehensive README with full command reference.

Architecture Principles

PrincipleImplementation
Commands are thinParse args → call service → format output. No business logic in commands.
Services are thickAll business logic, auth, caching, retries live in services.
MCP tools never throwReturn { success, data } or { success: false, error }.
Config is centralizedSingle ConfigManager singleton, validated with Zod schemas.
Progressive disclosureOnly show tools/features for configured integrations.
Bundle-friendlyNo dynamic requires. tsup bundles to single entry.
Skills over codeExtend agent capabilities via markdown skill files, not code changes.
Every action observableEventEmitter hooks fire on tool calls, inference, sessions. Full audit trail.
Safety by defaultSecret scanning, PR gates, budget alerts. Escalating safety profiles.
